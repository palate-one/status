# README와 기여 안내 문서 한국어 개편 설계

## 목표

`README.md`와 `CONTRIBUTING.md`를 처음 읽는 사람이 저장소의 역할과 다음 행동을 바로 이해할 수 있도록 자연스러운 한국어로 다듬는다. 운영 규칙, 보안 경계, 명령, 경로, 계산식은 바꾸지 않는다.

## 독자

- `README.md`: 상태 페이지를 확인하는 사람과 저장소 구조를 파악하려는 개발자
- `CONTRIBUTING.md`: 장애 공지, 점검 일정, 코드 또는 배포 설정을 변경하려는 기여자

## 문체

- 짧고 직접적인 한국어를 쓴다.
- 설명은 해요체보다 기술 문서에 자연스러운 평서형을 기본으로 한다.
- 코드 식별자, 명령, 파일 경로, API 경로는 원문을 유지하고 백틱으로 구분한다.
- 뜻이 흐려지지 않는 범위에서 불필요한 영어 혼용을 줄인다.

주요 표현은 다음처럼 정리한다.

| 기존 표현 | 기본 표현 |
| --- | --- |
| component | 구성요소 |
| sample | 관측값 |
| aggregate | 집계 |
| custom domain | 사용자 지정 도메인 |
| credential | 인증정보 |
| local / production | 로컬 / 운영 환경 |

고유 개념인 Worker, D1, HMAC, UTC, RFC 3339, API 이름과 코드 필드는 번역하지 않는다.

## README 구성

1. 저장소의 목적과 실제 상태 페이지 링크를 먼저 보여준다.
2. 시스템 구조와 데이터 흐름을 현재 구현에 맞게 설명한다.
3. 상태 판정, 가동률, 관측 범위 계산을 기존 의미 그대로 설명한다.
4. 장애 공지와 점검 일정의 작성 위치, 공개 금지 정보를 분명히 적는다.
5. 로컬 실행과 검증 명령을 그대로 유지한다.
6. 무료 운영 한도와 증거 경계를 간결하게 정리한다.

이미 완료된 D1 연결과 사용자 지정 도메인을 아직 해야 할 일처럼 표현하지 않는다. 다만 secret 값은 저장소에 두지 않고 운영 환경에서 관리한다는 원칙을 유지한다.

## CONTRIBUTING 구성

1. 작은 PR과 검증 책임을 먼저 설명한다.
2. 장애 공지와 점검 일정 작성 절차를 행동 순서대로 유지한다.
3. 공개 저장소에 올리면 안 되는 정보와 migration 불변 규칙을 강조한다.
4. 변경 종류별 검증 명령을 유지한다.
5. commit과 PR 규칙을 자연스러운 한국어로 설명한다.

## 제외 범위

- Worker, D1, GitHub Actions, 화면 문구 변경
- 배포 자동화나 새 운영 절차 추가
- 템플릿과 장기 운영 문서의 전면 개편
- 명령, 경로, API 계약, 상태 판정 규칙 변경

## 검증

- 두 문서의 링크와 코드 경로가 실제 파일과 일치하는지 확인한다.
- 기존 명령, 수식, 상태 조건이 빠지거나 달라지지 않았는지 diff로 확인한다.
- token, secret, 이메일, 계정 식별자 같은 비공개 정보가 추가되지 않았는지 검사한다.
- `bun run conventions:test`와 `git diff --check`를 실행한다.
